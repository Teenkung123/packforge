# PackForge

PackForge is a client-side Minecraft mod that helps large resource packs load faster. It supports Fabric, Forge, and NeoForge.

It is mainly designed for large server resource packs, including packs generated by ItemsAdder, ModelEngine, and other heavily customized setups.

Minecraft normally searches through a resource pack many times while loading it. With a large pack, this can make the loading screen take a long time, especially when the pack contains thousands of models, textures, sounds, or JSON files.

PackForge improves this process by building a fast internal index when a resource pack is loaded. Minecraft can then find files through the index instead of repeatedly scanning the entire ZIP archive.

## What PackForge Does

- Speeds up loading and reloading of large zipped resource packs
- Reduces repeated ZIP scans during model, item, texture, sound, and namespace discovery
- Helps shorten loading screens when joining servers with large custom packs
- Includes optional protection against oversized texture atlases
- Provides configurable loading information, summaries, timing diagnostics, and recovery features
- Works entirely in memory and never modifies the original resource-pack files

PackForge is useful for ordinary resource packs too, but the largest improvement is normally seen with packs containing many thousands of files.

## How It Works

Without an index, Minecraft and other resource-loading code may repeatedly walk through the same ZIP archive to locate different files. That repeated work becomes expensive as the pack grows.

PackForge reads the archive structure once, creates an internal lookup index, and reuses it for later resource requests. The index is discarded when the pack is closed or replaced.

This optimization does not change the contents of the pack or permanently cache server resources outside Minecraft's normal files.

[![PackForge 1.0 compared with vanilla Minecraft](https://img.youtube.com/vi/Gq3cOiEBZ_Q/maxresdefault.jpg)](https://www.youtube.com/watch?v=Gq3cOiEBZ_Q)

[![PackForge 1.2 compared with Quick Pack](https://img.youtube.com/vi/Jcnso9NeA9M/maxresdefault.jpg)](https://www.youtube.com/watch?v=Jcnso9NeA9M)

**PackForge 1.2 compared with [Quick Pack](https://modrinth.com/mod/quick-pack) by DrexHD**

In this test, PackForge 1.2 loaded the same pack in 9.37 seconds, compared with 16.25 seconds using PackForge 1.0. The improvement came primarily from further font-loading optimization.

The test pack contained approximately:

- 28,000 archive entries
- 9,800 textures
- 10,700 model files
- 191 namespaces
- More than 61 MiB of extracted data

For that workload, normal resource discovery performed around 4,600 full ZIP scans and more than 130 million entry checks. PackForge avoids most of those repeated scans by indexing the ZIP once per reload.

Results depend on the computer, storage device, Java runtime, installed mods, and structure of the resource pack. These benchmarks show the tested workloads and should not be treated as a guaranteed loading time for every pack.

## Atlas Overflow Protection

Some very large resource packs can fail to load on weaker or older GPUs because the final texture atlas becomes too large.

PackForge includes optional atlas protection that can downscale oversized textures in memory so the pack has a better chance of loading successfully. Most normal block and item textures should look unchanged, although heavily downscaled textures may appear slightly softer.

Atlas protection does not modify the resource pack. It only creates smaller temporary images while Minecraft is loading the pack.

The feature can be configured through `config/packforge.json` or PackForge's in-game configuration screen. Atlas retry recovery is disabled by default because retrying can temporarily use more memory.

## Installation

1. Download the correct PackForge JAR from [Modrinth](https://modrinth.com/mod/packforge).
2. Install Fabric Loader, Forge, or NeoForge for the selected Minecraft version.
3. Place the PackForge JAR in the instance's `mods` folder.
4. Launch Minecraft once to generate the configuration file.

PackForge's Fabric build uses Fabric Loader directly and does not require Fabric API. Mod Menu is an optional configuration-screen integration. Required internal libraries are embedded in the PackForge JAR.

## Configuration

The configuration file is located at:

```text
config/packforge.json
```

Most players can use the defaults. Individual optimizations and diagnostic features can be enabled or disabled separately. Resource packs can be reloaded with `F3 + T` after changing reload-related settings, although restarting Minecraft is recommended after changing major startup options.

Every supported PackForge build exposes its configuration screen through the white cog button beside the bottom resource-pack screen actions. The button finds a free slot instead of assuming a fixed position, so it can coexist with configuration buttons added by mods such as Entity Texture Features. Fabric users can also open the same screen through Mod Menu when it is installed; Forge and NeoForge expose it through their normal mod-list configuration entry.

The screen only shows features implemented for the selected Minecraft version. Cancel or Escape discards the draft, while Done saves the complete configuration atomically and preserves settings that are unavailable on older versions.

Notable options include:

- ZIP indexing and optional pooled ZIP reads
- Loading status text and reload summary notifications
- Loading-screen fade control
- Atlas size limits and optional stitch retry recovery
- Model, font, shader, and startup diagnostics on supported versions

Legacy 1.21.x artifacts expose all 21 options in the Reload tab, including loading progress, fade control, reload toasts, listener and shader diagnostics, model parsing, font preparation and bitmap caching, and timing-only atlas decode batching. Minecraft 1.20.1 exposes the same set except font-provider preselection, which has no corresponding vanilla preparation phase in that release.

The Large Atlas Fixer and Startup Optimizer tabs remain exclusive to current 26.x builds. Legacy atlas support records native source/decode/stitch/mipmap/upload work and batches native decode suppliers; it does not enable atlas caps, retry/recovery, UV clamping, parallel mipmap generation, or experimental splitting.

## Compatibility

PackForge is designed to work alongside commonly used client optimization and resource-pack mods, including:

- Sodium
- Iris
- ImmediatelyFast
- FerriteCore
- Lithium
- Continuity
- CIT Resewn

Compatibility can depend on the exact Minecraft version, loader, and mod combination. If a combination is not listed, that does not necessarily mean it is incompatible.

OptiFine and OptiFabric are not officially supported and have not been fully tested.

## Reporting Problems

Please use the [GitHub issue tracker](https://github.com/Teenkung123/packforge/issues) for reproducible bugs.

Include the following information when possible:

- Minecraft version
- Mod loader and loader version
- PackForge version
- Full `latest.log` or crash report
- Relevant resource-pack and mod list
- Steps needed to reproduce the problem

Large resource packs do not need to be shared publicly. A private download, reduced test pack, or list of the files that trigger the problem can still be useful.

## Building From Source

![gradle](https://cdn.jsdelivr.net/npm/@intergrav/devins-badges@3/assets/compact/built-with/gradle_vector.svg)

Build one target with:

```text
gradlew.bat buildTarget -Ppackforge_target=mc26_1_to_26_2 --no-daemon
```

Build every supported target with:

```text
gradlew.bat buildAllSupported --no-daemon
```

The full build produces 17 artifacts and verifies filenames, Java class versions, mixin compatibility, loader ranges, Minecraft ranges, generated pack metadata, and target capability metadata.
