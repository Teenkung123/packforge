# Neutral benchmark analysis

Python 3.10+, standard library only. This does not launch Minecraft or inspect mod code.

```
python benchmarks/analysis/benchmark.py schedule --output schedule.json
python benchmarks/analysis/benchmark.py analyze --schedule schedule.json --manifests results --output report.json --markdown report.md
python -m unittest discover -s benchmarks/analysis/tests -v
```

The launcher adapter must write one JSON manifest per scheduled process and a separate observer JSONL file. Paths in manifests are relative to that manifest. Failed/missing runs invalidate their cell, not disappear from statistics. Keep original raw events and manifests. `analyze` returns 0 only when every required cell passes; 1 indicates failed/incomplete admission, 2 invalid input.

All shown keys are required (`orderedPacks`, `artifacts`, and `configs` must be nonempty). Manifest values must describe the actual launched process and files, not intended settings. The adapter must snapshot/hash inputs before launching, verify after exit, and reject changed inputs. JVM/loader/game/hardware/graphics/ordered packs must match across compared modes within a cell. Artifact and config identities must be stable within each cell/mode; they can differ between modes. The observer artifact must be identical across all modes. `artifacts` includes every enabled mod; `configs` includes every relevant configuration. Mode `vanilla` means loader plus observer. Artifacts require `packforge` for current/corrected/candidate and `quickpack` for quickpack. Fresh processes are not cold-filesystem-cache measurements.

`optionsSnapshotPinned` must be JSON `true`: the runner must start from a pinned **complete** `options.txt` generated by an untimed private preflight. `effectiveOptions` must contain the full postflight parsed options file as a nonempty map of string keys to string values, including empty values and unknown/generated keybindings. The abbreviated example shows only the required critical fields: language, Unicode/Japanese glyph choices, filtering, mip levels, graphics preset, pack selection, inactivity limiter, VSync, and FPS limit. Production manifests must include every actual key, not just that subset. `configs` must include the actual full-file `options.txt` SHA-256. The entire effective map is compared exactly across modes without an ignore list; loader-generated differences require evidence and a later explicit decision. Missing snapshot, incomplete critical fields, or altered language/font/texture settings reject headline admission. Full-file hashes are stable within each mode and effective values must match across modes; map equality does not depend on options-file line order.

The analyzer additionally requires the runner attestations `valid: true`, `inputsUnchanged: true`, and `timeout: false`, with actual JSON boolean values. Missing or invalid attestations reject even a process with exit code zero and a complete event stream. `inputsUnchanged` must come from the before/after input verification; it is not inferred from successful observer completion.

For comparison, `context.jvmArgs` may omit only the two per-process observer properties `-Dpackforge.benchmark.sessionId=` and `-Dpackforge.benchmark.output=`; the manifest's actual `command` must preserve them. This matches the launcher adapter. Keep every other JVM argument and its order unchanged. Do not broadly replace run IDs, directory prefixes, classpath elements, heap sizes, or arbitrary property values: those differences can change performance. The analyzer deliberately performs exact equality on this comparison list and does not silently normalize mismatches. Game-directory arguments are game arguments, not JVM arguments.

`context.runtimeEnvironment` is required and contains **only `TEMP` and `TMP`**, both the same absolute path to this repository's private `.gradle/modernization-temp` directory. The runner must set these values in the child environment before launch and record the actual values; inherited system temporary directories are not acceptable. The analyzer validates the private destination and compares this map across modes like the JVM arguments. This pins the Windows temporary-directory condition involved in Forge's background HTTP client initialization. Earlier preflight manifests lacking the map are not headline evidence. Other environment variables must not be dumped into this field.

Every event has `schema: 1`, matching `sessionId`, `event`, integer `epochMillis`, integer `nanoTime`, integer `jvmUptimeMillis`, integer `reloadIndex`, and actual JSON boolean `windowActive: true`. The observer samples actual client/GLFW focus and emits an error on lost focus; the runner must not manufacture activity. Missing, false, or nonboolean activity on any qualifying event rejects the process. Events must appear in this order: `ready` (index -1), then `reload_requested`, `reload_complete`, `frame_ready` for index 0 (priming), then the same triplet for indexes 1 through 5, then `complete` (index 5). Any `error`, missing, extra, duplicate, cancelled, mismatched session, nonmonotonic clock or out-of-order event rejects the process. Startup is `ready.epochMillis - processStartedEpochMillis`; warm reload request-to-frame and request-to-complete durations use same-process nanoseconds. Benchmark options pin `inactivityFpsLimit: minimized` to avoid AFK throttling; observer rejection of short/long AFK throttling and iconification remains required in addition to event activity checks.

Every qualifying event also requires integer `framebufferWidth` and `framebufferHeight` equal to `context.graphicsSettings.width` and `.height`; expected dimensions are positive integers. These are actual framebuffer pixels, not merely requested window size. `ready` and every `frame_ready` additionally require `activePackIds`, the ordered, unique pack IDs returned by `resourceManager.listPacks()`. Every `orderedPacks` entry must appear in that order, using its `file/`-prefixed ID (without doubling an existing prefix). The complete observed stack must remain unchanged within a process and across repeated processes of a mode.

Across modes, PackForge current/corrected/candidate require identical complete stacks. Reference comparisons preserve the complete loader/base/file-pack order but permit only optimizer-owned built-ins below the primary pack in Minecraft's low-to-high priority order. The explicit allowlist is `packforge`, `mod/packforge`, `mod:packforge`; Quick Pack accepts stems `quickpack`, `quick-pack`, `quick_pack`, each bare or prefixed with `mod/` or `mod:`. The corresponding optimizer must actually be present in the manifest. All other differences fail admission rather than being silently dropped. Thus unfamiliar loader naming needs evidence and an explicit contract update, not a broad prefix exception. Raw stacks, normalized stacks, and all differences from vanilla are retained in JSON and changed modes are noted in Markdown. Pack-ID checks establish active-pack identity/order only; they do not replace separate resource-content correctness verification. Earlier preflights without these fields are not headline evidence.

On **9 September 2026**, the user approved reducing vanilla and matching Quick Pack reference samples to **three fresh processes per cell**. Current, corrected, and candidate remain at **ten** processes each. Every process still performs one priming reload and five measured reloads. The default six 26.1.2/26.2 × Fabric/Forge/NeoForge cells therefore contain **198 processes** without Quick Pack (33 per cell). Enable Quick Pack only with `--quickpack-cell 26.1.2-fabric` (repeatable) after verifying a matching released binary; each enabled cell adds three reference processes. `--companion-workload small` (repeatable) adds the same six cells and sampling design for that workload.

Schedules explicitly record `primaryBlocks: 10`, `referenceBlocks: 3`, `referenceBlockIndices: [0, 4, 9]`, and each cell's `processesPerMode`. Reference blocks are spread deterministically through the paired experiment, never selected after observing results. `--reference-blocks 10` restores ten reference processes; integer values 1–10 are supported with deterministic evenly spread positions (one reference uses block 4). A missing required reference run still invalidates its cell. Unavailable Quick Pack remains absent rather than inventing samples. Existing schedules without these explicit count fields must be regenerated; no implicit conversion occurs.

Main gates remain candidate versus current using **ten paired process samples**, not the reduced reference set. All other modes are reported, never substituted as the baseline. Each process contributes one median of its five measured reloads; process-level startup and reload samples are paired by block for seeded bootstrap confidence intervals. Headline p95 is the interpolated p95 of those ten process-level samples, not 50 pseudoreplicated reloads. Reference modes report valid/required sample counts and descriptive medians only, without p95 or significance claims. No failures or outliers are discarded. Confidence intervals are percentile 95% intervals from 10,000 paired bootstrap resamples of the median improvement; they are not a multiple-testing-adjusted familywise claim.
